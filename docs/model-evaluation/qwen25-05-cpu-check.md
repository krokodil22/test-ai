# Проверка плохого русского Qwen2.5 0.5B

28 октября 2026 года получен браузерный отчёт с шестью нейтральными вопросами.
Все 12 ресурсов прошли SHA-256 проверку; история очищалась перед каждым вопросом,
temperature 0, top_p 1. На русском модель ответила `3` на `2 + 2`, выдала
бессмысленный рецепт и повторяющееся неверное объяснение времён года.

## Что фактически проверено

Скачать исходную `Qwen/Qwen2.5-0.5B-Instruct` не удалось: сетевой шлюз возвращал
HTTP 403 для Hugging Face даже после разрешения сетевого доступа.
**Исходные BF16/FP32-веса в этой проверке не использовались.**

Вместо этого закреплённые браузерные MLC-веса q4f16_1 восстановлены в матрицы
для независимой реализации Qwen2 в Transformers 5.3.0 / PyTorch 2.6.0+cpu.
При восстановлении сохранены FP16-округление и порядок упаковки MLC, затем
вычисления шли на CPU в FP32. Использованы все 267 тензоров, тот же токенизатор,
шаблон Qwen2, системная инструкция, вопросы и пределы ответа.
Это не возвращает точность исходных весов: потерянные при сжатии значения
восстановить переводом в FP32 невозможно.

| Проверка | Браузер | Независимый CPU |
| --- | --- | --- |
| `2 + 2`, русский | `3` | `3`, дословное совпадение |
| `2 + 2`, английский | `4` | `4`, дословное совпадение |
| Омлет, русский | «омлетный орех», бессмысленные шаги | «Запейте омлетный овощной…», многократные повторы |
| Омлет, английский | Связнее, но яйца предлагается разбить повторно | Та же ошибка с повторным разбиванием яиц |
| Времена года, русский | Повторы про «законченный год/месяц» | Дословно тот же неверный ответ |
| Времена года, английский | Неверные причинные связи | Неверная причинная связь; текст короче |

Три из шести текстов совпали полностью. Все три русские задачи провалены и
при независимом CPU-вычислении. Различия остальных текстов допустимы при
FP32/FP16: небольшие различия вычислений меняют выбор следующего токена.
Замер времени облачного CPU не характеризует скорость пользовательского GPU.

Полные тексты и условия:

- [CPU-результаты](reports/qwen25-05-mlc-cpu-diagnostics.json).
- [Парное сравнение с браузером](light-cpu-browser-check.json); без данных об
  устройстве и пользовательской переписки, только фиксированные тестовые вопросы.

## Вывод и следующий контроль

Грубые ошибки текущего Q4-комплекта воспроизводятся вне WebLLM/WebGPU.
Замена только библиотеки выполнения не имеет подтверждённого основания.
Этот результат не доказывает отсутствие всех ошибок GPU и не позволяет
разделить ограничения исходной модели и дефект/потери её квантизации.

Для разделения причин нужен контроль **исходных BF16/FP32-весов этой же 0.5B**.
Профиль закреплён в `scripts/candidates/qwen2.5-0.5b.json`. Если исходная модель
лучше, следующий кандидат — менее сильное сжатие или конверсия с сохранением
точности embeddings/output. Увеличится размер и расход памяти; качество до
проверки не обещается. Если исходная модель также проваливает вопросы, нужен
другой кандидат, прошедший эти тесты до подключения к сайту.

Ни модель по умолчанию, ни параметры генерации сайта этой проверкой не изменены.

## Воспроизведение

После подготовки лёгкой модели (`npm run model:download:light`) и установки
CPU-зависимостей из `scripts/reference-requirements.txt` в отдельное окружение:

```sh
python scripts/run-mlc-cpu-reference.py --verify-only
python -m unittest discover -s tests/python -v
python scripts/run-mlc-cpu-reference.py --threads 4 \
  --output .cache/reference/qwen25-05-mlc-cpu-diagnostics.json
```

Для исходного контроля при доступном Hugging Face:

```sh
npm run reference:download -- --profile scripts/candidates/qwen2.5-0.5b.json \
  --output .cache/reference/qwen25-05-original
python scripts/run-reference.py --profile scripts/candidates/qwen2.5-0.5b.json \
  --model .cache/reference/qwen25-05-original --dtype float32 --threads 4 \
  --output .cache/reference/qwen25-05-original-diagnostics.json
```

Все Python-вычисления нужны разработчику. На сайте по-прежнему только
статические файлы и локальная браузерная генерация.
