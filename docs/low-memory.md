# Экономичная библиотека выполнения Qwen3.5 4B

Это пробный режим для устройств с небольшой памятью. Веса q4f16_1, токенизатор,
системный запрос, параметры выборки, контекст 4096 и предел ответа 512 токенов
сохранены. Четырёхбитные веса остаются теми же; повторная квантизация не выполнялась.
Численно тождественные ответы и ускорение не обещаются: изменилась компиляция.

## Использование

На главной странице откройте «Настройки и данные». Если модель запущена,
нажмите «Освободить память», затем выберите «Режим памяти → Экономичный — пробный»
и запустите модель. Выбор сохраняется локально и доступен также на страницах
сравнения и диагностики. Обычная сборка остаётся вариантом по умолчанию и
доступна для возврата. Менять режим во время загрузки или генерации нельзя.

В браузере дополнительно загружается только `model-low-memory.wasm` — 6 491 148
байт. Уже сохранённые 82 ресурса весов и исходный `.tar` подходят без изменений.
Саму модель не надо удалять или скачивать заново. Дополнительный WASM также
проверяется по SHA-256 и сохраняется в `webllm/wasm`. Удаление модели очищает и его.

Все страницы с генерацией используют один Web Lock на origin. Пока в одной
вкладке загружается или работает модель, вторая копия не выделяет память.
Выгрузка, закрытие вкладки, ошибка или отмена освобождают Worker и блокировку.
Основной чат теперь завершает Worker также при уходе со страницы. Уже открытые
вкладки старой версии нужно закрыть перед проверкой обновления.

Проверка кеша в диагностике хеширует поток частями; она больше не читает целый
крупнейший тензор на 317,8 МБ в `ArrayBuffer` поверх уже запущенной модели.

## Что изменилось в компиляции

| Параметр | Обычный | Экономичный |
| --- | ---: | ---: |
| Максимальный batch size в WASM | 128 | 1 |
| Размер обработки запроса в WASM | 1024 | 256 |
| Контекст приложения | 4096 | 4096 |
| Максимальный контекст в WASM | 262144 | 4096 |
| Рекуррентная история приложения | 1 | 1 |

WebLLM 0.2.86 читает размер обработки из `_metadata` WASM. Поле
`prefill_chunk_size` в настройках JS не меняет скомпилированный размер, поэтому
оно удалено из `MODEL_CHAT_OPTIONS`. Это новая сборка, а не переименование файла.

Оценки временных буферов из метаданных компилятора, **не замеры всей памяти**:

| Функция | Обычный, байт | Экономичный, байт |
| --- | ---: | ---: |
| `batch_decode` | 690 266 112 | 5 392 704 |
| `batch_prefill` | 261 734 400 | 36 284 416 |
| `batch_verify` | 1 151 713 280 | 289 570 816 |

`batch_verify` не используется обычным чатом. Эти величины нельзя складывать
или считать общим расходом RAM: остаются веса, состояния, драйвер, GPU, браузер
и ОС. Встроенная графика разделяет ОЗУ с системой. Работа и скорость на ноутбуке
с 8 ГБ ещё не проверены. Меньший размер обработки может замедлить длинный запрос,
а уменьшение давления на память может ускорить работу в целом — требуется замер.

## Подготовка статического сайта

```sh
npm run model:download
npm run runtime:prepare
npm run runtime:prepare -- --verify
npm run runtime:verify
npm run translator:download
npm run build
```

Сжатый исполняемый код без весов включён в `vendor/` и занимает 897 041 байт.
Это Apache-2.0 библиотека выполнения, а не параметры модели.
`scripts/low-memory-runtime.json` закрепляет SHA-256 сжатого и распакованного
кода. Подготовка работает без сети, использует временный `.part` и не принимает
повреждённый файл. Распакованный WASM находится в игнорируемом
`public/models/qwen35-4b/`; веса модели не добавляются в Git. На собственный хостинг копируется всё содержимое `dist/`.
После публикации браузер берёт файл с настроенного `VITE_MODEL_BASE_URL`,
без обращений к внешним хранилищам, CDN или API. Для отдельного хранилища действуют
те же HTTPS/CORS правила, что и для остальных ресурсов модели.

На GitHub Pages небольшой WASM публикуется рядом с `model-info.json`;
тяжёлый архив и его версия остаются прежними.

## Происхождение сборки

Компиляция выполнена MLC LLM CPU 0.20.0.dev0 и TVM CPU 0.20.0 из пакетов:

- `https://github.com/mlc-ai/package/releases/download/v0.9.dev0/mlc_llm_cpu-0.20.0.dev0-py3-none-manylinux_2_28_x86_64.whl`
- `https://github.com/mlc-ai/package/releases/download/v0.9.dev0/mlc_ai_cpu-0.20.0-py3-none-manylinux_2_28_x86_64.whl`

SHA-256 обоих wheel закреплены в `scripts/low-memory-runtime.json`. Использованы
Python 3.12, Emscripten 3.1.69 (Debian `3.1.69+dfsg-3`), Binaryen 133,
цель `webgpu:generic` без subgroups. Пакет TVM содержит LLVM 21; штатный
Binaryen из Debian не понимает все его признаки, поэтому взят Binaryen 133.

Команда в настроенном окружении MLC с подготовленными emcc runtime-зависимостями:

```sh
python -m mlc_llm compile public/models/qwen35-4b/resolve/main/mlc-chat-config.json \
  --device webgpu \
  --overrides 'prefill_chunk_size=256;max_batch_size=1;context_window_size=4096' \
  -o Qwen3.5-4B-q4f16_1_cs256-b1-webgpu.wasm
```

Для runtime-зависимостей использованы исходники `tvm/web`, `mlc_llm/web` и
`tvm_ffi` из этих же пакетов. Недостающие в wheel `tvm/include/tvm/support`,
`tvm/src/support` и `tvm/3rdparty/compiler-rt` взяты из
`mlc-ai/relax@201fa0001c81431ccce05419b442c47779ea917c` — закреплённого submodule
`mlc-ai/mlc-llm@8978ea9aec626d64096aaa92fbc89bda2e3ea802`.
`tvm/3rdparty/tvm-ffi` указывает на установленный `tvm_ffi`. Скомпилированы
`wasm_runtime.bc`, `tvmjs_support.bc`, `webgpu_runtime.bc` и `mlc_wasm_runtime.bc`.
Пользователю сайта и при обычной сборке Node/Vite эти инструменты не нужны:
достаточно `npm run runtime:prepare`, который проверяет и распаковывает код из `vendor/`.

## Проверка и пределы результата

`npm run runtime:verify` проверяет настоящий бинарный файл и его SHA-256,
загружает обе библиотеки штатным WASM-загрузчиком WebLLM 0.2.86 и выполняет
`_metadata` в CPU VM. Все 579 имён, форм и типов параметров совпадают между
сборками и с манифестом весов. Запуск шейдеров в этой проверке запрещён.
Отчёт: `docs/model-evaluation/low-memory-runtime-check.json`.

Тесты браузера отдельно проверяют блокировку вкладок, выгрузку без удаления
истории/кеша, смену режимов, загрузку только дополнительного WASM, повторное
использование кеша, возврат к обычному режиму и отказ при ошибке SHA-256.
Генерация в этих E2E подменена тестовым движком и не доказывает работоспособность
шейдеров. Выполнение новой библиотеки на настоящем совместимом GPU, русский
ответ, скорость и реальный расход RAM на устройстве с 8 ГБ нужно проверить
на целевом ноутбуке. В диагностический JSON включаются режим, SHA-256 WASM,
скомпилированные размеры обработки и batch size.
