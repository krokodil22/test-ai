# Великий Тетриканец — локальный ИИ-чат

Статический русскоязычный чат на TypeScript, Vite и WebLLM. Генерация выполняется **в Web Worker на GPU пользователя через WebGPU**. После сборки Node.js, сервер приложения, API нейросетей, аккаунты и ключи не нужны. История находится в `localStorage`, ресурсы модели — в Cache Storage этого браузера. Аналитики и телеметрии в приложении нет.

## Быстрый запуск

Нужен Node.js **24+**. Для общения нужен актуальный настольный Chrome, HTTPS (для разработки подходит `localhost`), доступный WebGPU-адаптер с `shader-f16` и достаточная память.

```bash
npm ci
npm run model:download
npm run dev
```

Откройте адрес из вывода Vite. Нажмите **«Скачать и запустить»**: ресурсы с вашего статического хостинга сохранятся в браузерном кеше, затем модель запустится. До нажатия кнопки модель не скачивается. Проверка HTTPS, WebGPU, адаптера, `shader-f16`, лимита буфера и создания GPU-устройства выполняется **до загрузки**. На следующем открытии запуск производится вручную кнопкой **«Запустить из кеша»**. Запущенный процесс между посещениями не сохраняется.

```bash
npm run model:download -- --verify  # проверить все локальные ресурсы без сети
npm run build                     # dist/: только статические файлы, вместе с моделью
npm run preview                   # локальная проверка сборки
```

`build` не скачивает модель автоматически. Для публикации с моделью на том же хостинге сначала выполните `model:download` и `--verify`. Для отдельного хранилища разместите модель там и задайте адрес ниже. Текущая подготовленная среда содержит полный скачанный комплект; все крупные файлы исключены из Git.

## Модель и ресурсы

| Параметр | Значение |
| --- | --- |
| Модель | Qwen2.5 1.5B Instruct, 1,5 млрд параметров, многоязычная, в том числе русский |
| Формат | `mlc-ai/Qwen2.5-1.5B-Instruct-q4f16_1-MLC`, 4-битные веса MLC для WebLLM; не Ollama/GGUF |
| Лицензия | Apache 2.0, текст в `licenses/Qwen2.5-APACHE-2.0.txt` и в каталоге ресурсов |
| Закреплённая ревизия весов | `9bd564b064631febf14deadcac492efb761d60c3` |
| Движок | WebLLM `0.2.79`, совместимая WASM-библиотека `v0_2_48`, обе версии закреплены |
| Загрузка в браузер | **879 804 433 байта ≈ 880 МБ (839,0 МиБ)**, 34 файла; JS интерфейса и движка дополнительно около 5,7 МБ без сжатия |
| Графическая память | Оценка WebLLM — **1629,75 МБ** при контексте 4096; рекомендуется 2–3 ГБ с запасом |
| Оперативная память | Ориентировочно 3–4 ГБ свободной RAM, желательно устройство с 8 ГБ RAM; реальные затраты зависят от браузера и GPU |
| Ограничения | Контекст 4096 токенов, ответ до 512 токенов, ввод до 1200 символов |

Версия 1.5B заменяет прежнюю 0.5B для повышения возможностей общения на русском. Используются опубликованные настройки Qwen: temperature 0.7, top_p 0.8, repetition_penalty 1.1; системное сообщение задаёт русский язык и явно разрешает вымысел в творческих заданиях. В WebLLM 0.2.79 нулевые frequency/presence-параметры обходят repetition_penalty, поэтому они явно очищаются в ChatOptions при загрузке модели. Проверка на настоящем пути reload защищает от возвращения этой ошибки. Ожидаемое улучшение качества необходимо проверять на реальных вопросах: сравнение двух моделей на GPU здесь не выполнялось. Возможны ошибки, повторы и неестественные формулировки. Это не надёжный источник медицинских, юридических или других ответственных рекомендаций.

Источники: [карточка оригинальной модели](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct), [MLC-ресурсы](https://huggingface.co/mlc-ai/Qwen2.5-1.5B-Instruct-q4f16_1-MLC), [WebLLM](https://github.com/mlc-ai/web-llm). Выбор WASM соответствует записи этой модели в закреплённой версии WebLLM. Не обновляйте только библиотеку или только WASM независимо друг от друга.

### Самостоятельное размещение всех ресурсов

```bash
npm run model:download
# Или скачать комплект для отдельного хранилища:
npm run model:download -- --output /path/to/model-storage/qwen2.5-1.5b
npm run model:download -- --output /path/to/model-storage/qwen2.5-1.5b --verify
```

Скрипт скачивает с официальных Hugging Face и GitHub, закрепляет ревизию, сверяет SHA-256 LFS-файлов, Git blob SHA-1 небольших файлов и заранее закреплённый SHA-256 WASM. TLS-проверка включена. Существующие файлы проверяются и используются повторно. Незаконченные `.part` удаляются; `model-info.json` появляется только после успешного получения всего комплекта. Флаг `--runtime-only` скачивает только WASM для диагностики и **не создаёт работоспособный комплект**.

```text
public/models/qwen2.5-1.5b/
├── model-info.json             # размер, ревизия, SHA-256 и список ресурсов
├── model.wasm                  # совместимая GPU-библиотека WebLLM
├── LICENSE
└── resolve/main/
    ├── mlc-chat-config.json
    ├── ndarray-cache.json
    ├── tokenizer.json
    ├── params_shard_0.bin … params_shard_29.bin
    └── README.md
```

Суффикс `resolve/main/` нужен из-за нормализации URL в WebLLM. Это локальное имя каталога; веса фактически закреплены на указанном commit SHA. Токенизатору WebLLM для этой модели нужен `tokenizer.json`; остальные исходные `vocab.json`, `merges.txt` и `tokenizer_config.json` не запрашиваются. WASM токенизатора и вспомогательный код выполнения уже включены в JS-пакет worker. Обязательных CDN во время работы сайта нет.

Не добавляйте веса, WASM и `dist` в Git. Они уже перечислены в `.gitignore`. Для скачивания при сборке нужны только `raw.githubusercontent.com`, `huggingface.co` и домен перенаправления файлов `us.aws.cdn.hf.co` (Hugging Face может менять CDN; разрешайте фактический официальный домен). При работе готового сайта эти домены не используются.

## Обновление с модели 0.5B

Повторно запустите **Publish GitHub Pages** после получения новых исходников. После публикации обновите страницу и нажмите «Скачать и запустить»: потребуется около **880 МБ** вместо 289 МБ. Затем начните **новый чат**, чтобы старые неудачные ответы не влияли на контекст. История остаётся доступной в боковой панели.

Кеш прежней модели 0.5B удаляется при явном запуске новой модели, без удаления переписки. Если собственное хранилище использует прежний URL, манифест проверяется по ID и закреплённой ревизии; несовместимые веса, токенизатор и WASM удаляются перед загрузкой новой версии. Кнопка очистки модели удаляет также распознанные прежние версии, сохраняя кеши других приложений.

Профиль модели, размеры, лицензионные сведения, ревизия и WASM определены в `scripts/model-source.json`. Сборка включает только активную модель из `public/models`, поэтому оставленные локально старые загрузки не увеличивают опубликованный сайт. Локальные старые файлы сохраняются. Workflow дополнительно проверяет размер `dist` перед публикацией (до 1 ГБ).

## Адрес ресурсов и HTTPS

Скопируйте `.env.example` в `.env.local` либо передайте переменные при сборке:

```dotenv
# Относительно адреса приложения: подходит и для /test-ai/, и для корня домена.
VITE_MODEL_BASE_URL=models/qwen2.5-1.5b/
VITE_BASE_PATH=./
```

Для общего отдельного хранилища:

```dotenv
VITE_MODEL_BASE_URL=https://assets.example.org/models/qwen2.5-1.5b/
VITE_BASE_PATH=./
```

При обновлении с 0.5B обновите `VITE_MODEL_BASE_URL`, если он задан вручную: новый каталог — `models/qwen2.5-1.5b/`. Затем нужна новая сборка. Каталог загрузчика загрузите целиком, сохранив структуру. Если модель размещена отдельно, можно скачать её сразу с `--output` вне `public`, чтобы она не дублировалась в `dist`.

Хранилище должно отвечать на GET/HEAD и при необходимости OPTIONS по HTTPS, с заголовками CORS, включая ошибки:

```http
Access-Control-Allow-Origin: https://owner.github.io
Vary: Origin
Access-Control-Allow-Methods: GET, HEAD, OPTIONS
Access-Control-Allow-Headers: Range
Access-Control-Expose-Headers: Content-Length, Content-Range, Accept-Ranges
```

Для публичных ресурсов допустим `Access-Control-Allow-Origin: *`; cookies и авторизация не используются. `Allow-Origin` содержит origin без пути `/test-ai/`. Отдавайте `.wasm` как `application/wasm`, JSON как `application/json`, бинарные части как `application/octet-stream`. Не перенаправляйте недостающие файлы на `index.html`; возвращайте 404. **Редиректы при загрузке в браузере запрещены**: используйте конечный адрес хранилища. Обновляя модель, меняйте URL каталога, чтобы старый кеш не смешался с новым.

Production HTML содержит CSP: `connect-src` разрешает только собственный origin и настроенный origin модели; `script-src` — собственные скрипты и компиляцию WASM. Обёртка fetch в worker дополнительно допускает только GET из настроенного каталога, без query-параметров, cookies, Referer и перенаправлений. Скрипт скачивания проверяет целостность всех ресурсов перед размещением. Дополнительная проверка SHA-256 в worker относится к запросам через fetch; собственный Cache.add WebLLM и чтение ранее сохранённого кеша эту проверку не вызывают. Политика из HTTP-заголовков вашего хостинга может быть строже — учтите настроенный origin и `'wasm-unsafe-eval'`. COOP/COEP для этой реализации не требуется.

HTTPS обязателен; исключение — loopback для разработки. CSP нельзя убирать ради загрузки постороннего скрипта. Приложение не переключается на удалённые API при ошибках.

## Публикация

### GitHub Pages

1. Отправьте исходники и lockfile в свой репозиторий. Не коммитьте `public/models` и `dist`.
2. В **Settings → Pages → Source** выберите **GitHub Actions**.
3. В Actions вручную запустите **Publish GitHub Pages** (`.github/workflows/pages.yml`). Workflow установит зависимости, выполнит модульные тесты, скачает и проверит модель, соберёт сайт с `VITE_BASE_PATH=/<имя-репозитория>/` и опубликует статический артефакт.
4. Откройте HTTPS-адрес Pages из завершившегося workflow в совместимом Chrome.

Для этого репозитория явная локальная сборка:

```bash
npm ci
npm run model:download
VITE_BASE_PATH=/test-ai/ npm run build
```

Для сайта `owner.github.io` в корне укажите `VITE_BASE_PATH=/`. Значение по умолчанию `./` также поддерживает корень и подкаталог без изменения сборки. Общий объём сайта с моделью — около 886 МБ без сжатия, ниже лимита опубликованного сайта Pages 1 ГБ. Публикация из этой среды не выполнялась.

### Обычный статический хостинг

```bash
npm ci
npm run model:download
npm run model:download -- --verify
npm run build
```

Загрузите **содержимое `dist/`** на HTTPS-хостинг, сохраняя каталоги. Никакой Node.js-процесс на сервере не нужен. При загрузке новой версии отключите устаревший кеш HTML; ресурсы с версионированными именами можно кешировать надолго. Веб-страница при новом открытии всё ещё требует доступа к хостингу — service worker для гарантированного офлайн-запуска страницы не добавлен. При этом веса и токенизатор повторно используются из Cache Storage.

## Работа с чатом и приватность

- Enter отправляет сообщение, Shift+Enter добавляет строку; IME-композиция не отправляет незавершённый текст.
- «Остановить» прерывает генерацию. Если worker завис и не обработал остановку за 6 секунд, он завершается принудительно; для продолжения потребуется снова запустить модель из кеша.
- «Новый чат» начинает пустой диалог, предыдущие чаты остаются в боковой панели. Максимум 30 чатов по 500 сообщений, без автоматического удаления. В настройках есть отдельные действия для удаления всей переписки и файлов модели, включая частично загруженные. Изменения истории синхронизируются между вкладками этого origin.
- Контекст строится в worker: системное сообщение и самые новые полные пары реплик, до безопасного бюджета, с резервом для 512 токенов ответа. Верхняя оценка числа токенов по UTF-8 байтам специально консервативна; длинная история раньше исключается из контекста, но остаётся видимой. Непомещающийся новый вопрос отклоняется понятной ошибкой.
- Markdown очищается DOMPurify. Исходный HTML выводится как текст. Изображения не загружаются, ссылки отображаются без переходов; это исключает скрытые запросы из текста ответа. Код подсвечивается локально; есть копирование кода и всего ответа.
- `localStorage` не зашифрован: история доступна другим пользователям того же профиля браузера, расширениям с соответствующим доступом и коду того же origin. Для полной изоляции размещайте приложение на выделенном origin.
- Владелец статического хостинга видит обычные запросы файлов и IP-адрес посетителя, но приложение **не отправляет тексты сообщений и ответы**. Никаких внешних API для генерации нет.
- Браузер вправе очищать кеш автоматически. Запрашивается persistent storage, но браузер может отказать. В приватном режиме сохранение между сессиями не гарантируется.

## Эксперимент: русский ответ через английский

Откройте в чате **Настройки и данные → Проверить перевод через английский**, либо `compare.html` на том же сайте. Страница открывается в текущей вкладке и завершает worker чата, чтобы не держать две копии модели в GPU. Общий кеш Qwen используется повторно; новых моделей, API-ключей или серверной генерации нет.

1. Нажмите «Запустить из кеша» (или выполните первую загрузку, если кеша нет).
2. Выберите рассказ про свинку, объяснение времён года, инструкцию или введите свой короткий текстовый вопрос.
3. Нажмите «Сравнить ответы». Одна и та же Qwen последовательно выполняет четыре независимых запуска: прямой русский ответ, перевод RU → EN, ответ на английском, перевод EN → RU.
4. Сравните русский язык, связность и смысл. Раскройте промежуточные тексты: ошибка может возникнуть как в английском ответе, так и в одном из переводов. Время прямого варианта и сумма трёх этапов измеряются отдельно; первоначальная загрузка модели в них не входит. Это одиночная выборка, а не статистический бенчмарк.
5. При необходимости сохраните JSON: он содержит завершённые сравнения этой вкладки, промежуточные тексты, времена, seed, модель и настройки. Данные скачиваются на устройство по кнопке и не отправляются на сервер.

Seed фиксирован на 42. Прямой и английский ответы используют текущие настройки генерации и лимит 512 токенов. Переводы используют temperature 0.1 и top_p 1; для обратного перевода доступно до 1024 токенов. Контекст проверяется перед каждым этапом. Обрезанный прямой ответ явно помечается, а обрезанный или пустой промежуточный перевод не передаётся дальше как полный. «Остановить» прерывает весь эксперимент; зависший worker завершается через 6 секунд.

**Это отдельный эксперимент, обычный чат продолжает отвечать напрямую на русском.** Он не добавляет записи в историю и не внедряет автоматический перевод в многошаговый диалог. Проверяется прежде всего качество обычных текстовых вопросов; сохранение кода и сложного Markdown при автоматическом переводе ещё потребует отдельной реализации. Итоговый перевод появляется после завершения трёх этапов. Не открывайте несколько вкладок с запущенной моделью одновременно на устройстве с небольшим объёмом GPU-памяти.

В этой облачной среде проверяются порядок этапов, отмена, передача промежуточных данных, кеш, экспорт и отсутствие передачи текстов по сети. E2E использует **тестовый движок**, явно помеченный на странице и в JSON (`testing: true`), и не подтверждает качество русского. В production такой подмены нет. Реальный эксперимент требует совместимого GPU у посетителя; `npm run test:gpu` при наличии GPU сохраняет настоящий JSON для человеческой оценки, не объявляя победителя автоматически.

## Проверки и фактические ограничения

```bash
npm test                       # модульные проверки контекста, адресов и ошибок
npm run test:e2e                # Chromium, реальный UI и worker, ТЕСТОВЫЙ движок
npm run build
npm run test:gpu                # production-сборка + настоящий WebLLM при наличии GPU
```

Playwright использует `/usr/bin/chromium`, если он установлен, иначе свой Chromium. Для своего браузера задайте `CHROMIUM_PATH`. На машине без браузера: `npx playwright install --with-deps chromium`. Тестовый движок и адаптер подменяются **только при сборке тестового сервера через `E2E_MOCK=1`**; в обычной сборке их нет. `test:gpu` не подменяет движок. Не публикуйте сборку с `E2E_MOCK=1`.

| Две остановки подряд, новый чат, независимое удаление истории и модели | Пройдены с тестовым движком |
| Ошибки скачивания, хеша, памяти, потери GPU; запрет постороннего URL | Обработка проверена контролируемыми ошибками тестового движка |
| Сетевой аудит | В тестовых диалогах только GET статических файлов с настроенного адреса; POST/тела запросов и тексты переписки отсутствуют |
| HTML/XSS, внешнее изображение и JavaScript-ссылка в истории | Не исполняются, внешних запросов нет |
| Миграция кеша 0.5B и устаревшей ревизии | Пройдена с тестовым движком: раздельные URL и сохранённый URL, переписка и чужие кеши сохраняются |
| Отдельное хранилище с CORS и без него | Настоящий второй origin на loopback: успешная загрузка и блокировка браузером при отсутствии CORS; генерация тестовая. Внешний HTTPS-хостинг не публиковался |
| Production-страница в корне и под `/test-ai/` | Пройдены проверки настоящих статических файлов |
| Адаптивный интерфейс 390×844 | Проверен в настольном Chromium с эмуляцией размера; это **не проверка телефона** |
| Настоящая генерация Qwen и реальный GPU-кеш/остановка | **Не подтверждены:** у обычного headless Chromium нет адаптера; SwiftShader даёт адаптер без `shader-f16`. Интеграционный тест помечается skipped, а не passed; добавлены реальные проверки исправления русской грамматики, перевода и рассказа из пользовательского отчёта; они требуют совместимого GPU. Нативный диагностический стенд Dawn/lavapipe загрузил настоящую модель, но не завершил сравнение рассказов за отведённое время; это не пройденная проверка качества |

Для окончательной проверки на целевом компьютере выполните `npm run test:gpu` с совместимым GPU либо пройдите в актуальном Chrome: первая загрузка → вопрос на русском → остановка длинного ответа → обновление страницы и запуск из кеша → очистка модели → отдельная очистка истории. В DevTools Network проверьте отсутствие запросов с текстом переписки и повторной загрузки частей модели. Тесты не заменяют проверку производительности, качества русского языка, реального дефицита видеопамяти и аппаратного сбоя.

**Совместимость с Яндекс Браузером, Safari, Firefox и телефонами не проверена и не обещается.** Для них предусмотрено сообщение о несовместимости; наличие названия WebGPU само по себе не гарантирует поддержку нужных возможностей. Публикация версии 1.5B и её проверка в живом GitHub Pages из этой среды не выполнялись.
