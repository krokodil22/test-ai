# Великий Тетриканец — локальный ИИ-чат

Статический русскоязычный чат на TypeScript, Vite и WebLLM. Генерация выполняется **в Web Worker на GPU пользователя через WebGPU**. Основная модель — Qwen3 1.7B; отдельная страница сравнивает русский ответ напрямую и вариант через английский с OPUS-MT. После сборки Node.js, сервер приложения, API нейросетей, аккаунты и ключи не нужны. История находится в `localStorage`, ресурсы модели — в Cache Storage этого браузера. Аналитики и телеметрии в приложении нет.

## Быстрый запуск

Нужен Node.js **24+**. Для общения нужен актуальный настольный Chrome, HTTPS (для разработки подходит `localhost`), доступный WebGPU-адаптер с `shader-f16` и достаточная память.

```bash
npm ci --ignore-scripts
npm run model:download
npm run translator:download  # для эксперимента; основной чат работает без переводчика
npm run dev
```

Откройте адрес из вывода Vite. Нажмите **«Скачать и запустить»**: ресурсы с вашего статического хостинга сохранятся в браузерном кеше, затем модель запустится. До нажатия кнопки модель не скачивается. Проверка HTTPS, WebGPU, адаптера, `shader-f16`, DecompressionStream, лимита буфера и создания GPU-устройства выполняется **до загрузки**. На следующем открытии запуск производится вручную кнопкой **«Запустить из кеша»**. Запущенный процесс между посещениями не сохраняется.

```bash
npm run model:download -- --verify  # проверить все локальные ресурсы без сети
npm run build                     # dist/: только статические файлы, вместе с моделью
npm run preview                   # локальная проверка сборки
```

`build` не скачивает модель автоматически. Для публикации с моделью на том же хостинге сначала выполните `model:download` и `--verify`; для страниц перевода также `translator:download` и `--verify`. `npm ci --ignore-scripts` устанавливает проверенные пакеты без ненужных Node/CUDA install-скриптов: в приложении используется браузерный WASM. Для отдельного хранилища разместите модель там и задайте адрес ниже. Текущая подготовленная среда содержит полный скачанный комплект; все крупные файлы исключены из Git.

## Модель и ресурсы

Перед загрузкой проверяется поддержка буфера WebGPU от **155 582 464 байт (148,4 МиБ)**: у Qwen3 больше embedding-тензор. Адаптеры с лимитом 128 МиБ не подходят, даже если им хватало памяти для прежней Qwen2.5. Обычно нужен лимит 256 МиБ или выше. Проверяется и остальной минимальный набор лимитов WebLLM: maxBufferSize от 256 МиБ, maxComputeWorkgroupStorageSize от 32 КиБ, maxStorageBuffersPerShaderStage от 10. При создании рабочего устройства устраняется слишком маленький fallback WebLLM 0.2.79 (128 МиБ): запрашивается требуемый моделью размер, без превышения возможностей адаптера.

| Параметр | Значение |
| --- | --- |
| Модель | Qwen3 1.7B, 1,7 млрд параметров, многоязычная, в том числе русский |
| Формат | `mlc-ai/Qwen3-1.7B-q4f16_1-MLC`, 4-битные веса MLC для WebLLM; не Ollama/GGUF |
| Лицензия | Apache 2.0, текст в `licenses/Qwen3-APACHE-2.0.txt` и в каталоге ресурсов |
| Закреплённая ревизия весов | `80b3abcec6c3b3f5355dc0cc99cc4fb578f192bc` |
| Движок | WebLLM `0.2.79`, совместимая WASM-библиотека `v0_2_48`, обе версии закреплены |
| Загрузка в браузер | **858 449 127 байт ≈ 858,4 МБ**, 34 ресурса, из них 30 gzip-архивов весов; JS интерфейса и движка дополнительно около 5,7 МБ без сжатия. После распаковки в Cache Storage — **984 300 605 байт ≈ 984,3 МБ** |
| Графическая память | Оценка WebLLM — **2036,66 МБ** при контексте 4096; рекомендуется 3–4 ГБ с запасом |
| Оперативная память | Ориентировочно 3–4 ГБ свободной RAM, желательно устройство с 8 ГБ RAM; реальные затраты зависят от браузера и GPU |
| Ограничения | Контекст 4096 токенов, ответ до 512 токенов, ввод до 1200 символов |

Qwen3 1.7B заменяет прежние Qwen2.5 0.5B и 1.5B. Обычный чат и эксперимент с переводом явно передают `extra_body.enable_thinking=false`. На странице сравнения рассуждений второй вариант передаёт `true`. Пустой служебный `<think>…</think>` в начале обычного ответа удаляется перед показом; непустые рассуждения в новом эксперименте отделяются от итогового ответа. Контекст ограничен 4096 токенами, prefill — 1024, в соответствии с WASM `ctx4k_cs1k`.

Настройки проекта для ответов: temperature 0.7, top_p 0.8, repetition_penalty 1.1. В WebLLM 0.2.79 нулевые frequency/presence-параметры обходят repetition_penalty, поэтому они явно очищаются в ChatOptions при загрузке; у перевода RU → EN они специально равны нулю. Модульная проверка использует настоящий путь reload библиотеки. Качество русского и сравнение двух способов ответа на новой Qwen3 **не проверены аппаратной генерацией в этой облачной среде**: нужен совместимый GPU. Возможны ошибки, повторы и неестественные формулировки.

Источники: [карточка оригинальной модели](https://huggingface.co/Qwen/Qwen3-1.7B), [MLC-ресурсы](https://huggingface.co/mlc-ai/Qwen3-1.7B-q4f16_1-MLC), [WebLLM](https://github.com/mlc-ai/web-llm). Выбор WASM соответствует записи этой модели в закреплённой версии WebLLM. Не обновляйте только библиотеку или только WASM независимо друг от друга.

### Самостоятельное размещение всех ресурсов

```bash
npm run model:download
# Или скачать комплект для отдельного хранилища:
npm run model:download -- --output /path/to/model-storage/qwen3-1.7b
npm run model:download -- --output /path/to/model-storage/qwen3-1.7b --verify
```

Скрипт скачивает с официальных Hugging Face и GitHub, закрепляет ревизию, сверяет SHA-256 LFS-файлов, Git blob SHA-1 небольших файлов и заранее закреплённый SHA-256 WASM. TLS-проверка включена. Существующие файлы проверяются и используются повторно. Незаконченные `.part` удаляются; `model-info.json` появляется только после успешного получения всего комплекта. Флаг `--runtime-only` скачивает только WASM для диагностики и **не создаёт работоспособный комплект**.

```text
public/models/qwen3-1.7b/
├── model-info.json             # размер, ревизия, SHA-256 и список ресурсов
├── model.wasm                  # совместимая GPU-библиотека WebLLM
├── LICENSE
└── resolve/main/
    ├── mlc-chat-config.json
    ├── ndarray-cache.json
    ├── tokenizer.json
    ├── params_shard_0.bin.gz … params_shard_29.bin.gz
    └── README.md
```

Суффикс `resolve/main/` нужен из-за нормализации URL в WebLLM. Это локальное имя каталога; веса фактически закреплены на указанном commit SHA. Токенизатору WebLLM для этой модели нужен `tokenizer.json`; остальные исходные `vocab.json`, `merges.txt` и `tokenizer_config.json` не запрашиваются. WASM токенизатора и вспомогательный код выполнения уже включены в JS-пакет worker. Обязательных CDN во время работы сайта нет.

Не добавляйте веса, WASM и `dist` в Git. Они уже перечислены в `.gitignore`. Для скачивания при сборке нужны только `raw.githubusercontent.com`, `huggingface.co` и домен перенаправления файлов `us.aws.cdn.hf.co` (Hugging Face может менять CDN; разрешайте фактический официальный домен). При работе готового сайта эти домены не используются.

## Обновление с Qwen2.5 0.5B и 1.5B

Повторно запустите **Publish GitHub Pages** после получения новых исходников. После публикации обновите страницу и нажмите «Скачать и запустить»: для Qwen3 потребуется новая загрузка около **858,4 МБ**. Затем начните **новый чат**, чтобы старые неудачные ответы не влияли на контекст. История остаётся доступной в боковой панели.

Кеши прежних моделей Qwen2.5 0.5B и 1.5B удаляются при явном запуске новой модели, без удаления переписки и OPUS-MT. Если собственное хранилище использует прежний URL, манифест проверяется по ID и закреплённой ревизии; несовместимые веса, токенизатор и WASM удаляются перед загрузкой новой версии. Кнопка очистки модели удаляет также распознанные прежние версии, сохраняя кеши других приложений.

Файлы весов публикуются как `.bin.gz`, чтобы Qwen3 вместе с переводчиком помещалась в лимит GitHub Pages. Загрузчик проверяет исходные файлы по закреплённой ревизии, сжимает веса, записывает оба SHA-256 в model-info.json и удаляет только избыточные несжатые файлы из нового каталога. Старые версии на диске разработчика сохраняются. Повторный запуск использует проверенные архивы без повторного скачивания весов. `--verify` проверяет архивы и их содержимое.

Перед reload WebLLM worker скачивает архивы, проверяет SHA-256, распаковывает по одному файлу и сохраняет обычные несжатые URL в штатных кешах WebLLM. Поддерживается и HTTP Content-Encoding:gzip, когда браузер уже распаковал ответ. Проверяется исходное содержимое в обоих случаях. WebLLM читает готовый кеш; ненужного запроса `.bin` на статическом хостинге нет. Файлы, уже подготовленные приложением и помеченные проверенным SHA-256, используются повторно. После удаления модели эти записи удаляются вместе с метаданными.

Профиль модели, размеры, лицензионные сведения, ревизия и WASM определены в `scripts/model-source.json`. Сборка включает только активную модель из `public/models`, поэтому оставленные локально старые загрузки не увеличивают опубликованный сайт. Локальные старые файлы сохраняются. Workflow дополнительно проверяет размер `dist` перед публикацией (до 1 ГБ).

## Адрес ресурсов и HTTPS

Скопируйте `.env.example` в `.env.local` либо передайте переменные при сборке:

```dotenv
# Относительно адреса приложения: подходит и для /test-ai/, и для корня домена.
VITE_MODEL_BASE_URL=models/qwen3-1.7b/
VITE_BASE_PATH=./
```

Для общего отдельного хранилища:

```dotenv
VITE_MODEL_BASE_URL=https://assets.example.org/models/qwen3-1.7b/
VITE_BASE_PATH=./
```

При обновлении с Qwen2.5 0.5B или 1.5B обновите `VITE_MODEL_BASE_URL`, если он задан вручную: новый каталог — `models/qwen3-1.7b/`. Затем нужна новая сборка. Каталог загрузчика загрузите целиком, сохранив структуру. Если модель размещена отдельно, можно скачать её сразу с `--output` вне `public`, чтобы она не дублировалась в `dist`.

Хранилище должно отвечать на GET/HEAD и при необходимости OPTIONS по HTTPS, с заголовками CORS, включая ошибки:

```http
Access-Control-Allow-Origin: https://owner.github.io
Vary: Origin
Access-Control-Allow-Methods: GET, HEAD, OPTIONS
Access-Control-Allow-Headers: Range
Access-Control-Expose-Headers: Content-Length, Content-Range, Accept-Ranges
```

Для публичных ресурсов допустим `Access-Control-Allow-Origin: *`; cookies и авторизация не используются. `Allow-Origin` содержит origin без пути `/test-ai/`. Отдавайте `.mjs` и `.js` как `text/javascript`, `.wasm` как `application/wasm`, JSON как `application/json`, бинарные части как `application/octet-stream`. Не перенаправляйте недостающие файлы на `index.html`; возвращайте 404. **Редиректы при загрузке в браузере запрещены**: используйте конечный адрес хранилища. Обновляя модель, меняйте URL каталога, чтобы старый кеш не смешался с новым.

Production HTML содержит CSP: `connect-src` разрешает только собственный origin и настроенные origin Qwen и переводчика; `script-src` — собственные скрипты и компиляцию WASM. Обёртка fetch в worker дополнительно допускает только GET из настроенного каталога, без query-параметров, cookies, Referer и перенаправлений. Скрипт скачивания проверяет целостность всех ресурсов перед размещением. Worker заранее проверяет данные и заполняет кеш WebLLM, включая распаковку весов; поэтому собственный Cache.add WebLLM не скачивает архивы в обход этой проверки. При повторном запуске помеченные проверенные записи не хешируются заново. Политика из HTTP-заголовков вашего хостинга может быть строже — учтите настроенный origin и `'wasm-unsafe-eval'`. COOP/COEP для этой реализации не требуется.

HTTPS обязателен; исключение — loopback для разработки. CSP нельзя убирать ради загрузки постороннего скрипта. Приложение не переключается на удалённые API при ошибках.

## Публикация

### GitHub Pages

1. Отправьте исходники и lockfile в свой репозиторий. Не коммитьте `public/models`, `public/translations` и `dist`.
2. В **Settings → Pages → Source** выберите **GitHub Actions**.
3. В Actions вручную запустите **Publish GitHub Pages** (`.github/workflows/pages.yml`). Workflow установит зависимости, выполнит модульные тесты, скачает и проверит Qwen и переводчик, соберёт сайт с `VITE_BASE_PATH=/<имя-репозитория>/` и опубликует статический артефакт.
4. Откройте HTTPS-адрес Pages из завершившегося workflow в совместимом Chrome.

Для этого репозитория явная локальная сборка:

```bash
npm ci --ignore-scripts
npm run model:download
npm run translator:download
VITE_BASE_PATH=/test-ai/ npm run build
```

Для сайта `owner.github.io` в корне укажите `VITE_BASE_PATH=/`. Значение по умолчанию `./` также поддерживает корень и подкаталог без изменения сборки. Общий объём сайта с моделью — около 970,5 МБ с обоими комплектами ресурсов, ниже лимита опубликованного сайта Pages 1 ГБ. Публикация из этой среды не выполнялась.

### Обычный статический хостинг

```bash
npm ci --ignore-scripts
npm run model:download
npm run model:download -- --verify
npm run translator:download
npm run translator:download -- --verify
npm run build
```

Загрузите **содержимое `dist/`** на HTTPS-хостинг, сохраняя каталоги. Никакой Node.js-процесс на сервере не нужен. При загрузке новой версии отключите устаревший кеш HTML; ресурсы с версионированными именами можно кешировать надолго. Веб-страница при новом открытии всё ещё требует доступа к хостингу — service worker для гарантированного офлайн-запуска страницы не добавлен. При этом веса и токенизатор повторно используются из Cache Storage.

## Работа с чатом и приватность

- Enter отправляет сообщение, Shift+Enter добавляет строку; IME-композиция не отправляет незавершённый текст.
- «Остановить» прерывает генерацию. Если worker завис и не обработал остановку за 6 секунд, он завершается принудительно; для продолжения потребуется снова запустить модель из кеша.
- «Новый чат» начинает пустой диалог, предыдущие чаты остаются в боковой панели. Максимум 30 чатов по 500 сообщений, без автоматического удаления. В настройках есть отдельные действия для удаления всей переписки и файлов модели, включая частично загруженные. Изменения истории синхронизируются между вкладками этого origin.
- Контекст строится в worker: системное сообщение и самые новые полные пары реплик, до безопасного бюджета, с резервом для 512 токенов ответа. Верхняя оценка числа токенов по UTF-8 байтам специально консервативна; длинная история раньше исключается из контекста, но остаётся видимой. Непомещающийся новый вопрос отклоняется понятной ошибкой.
- Markdown очищается DOMPurify. Исходный HTML выводится как текст. Изображения не загружаются, ссылки отображаются без переходов; это исключает скрытые запросы из текста ответа. Код подсвечивается локально; есть копирование кода и всего ответа.
- `localStorage` не зашифрован: история доступна другим пользователям того же профиля браузера, расширениям с соответствующим доступом и коду того же origin. Для полной изоляции размещайте приложение на выделенном origin.
- Владелец статического хостинга видит обычные запросы файлов и IP-адрес посетителя, но приложение **не отправляет тексты сообщений и ответы**. Никаких внешних API для генерации нет.
- Браузер вправе очищать кеш автоматически. Запрашивается persistent storage, но браузер может отказать. В приватном режиме сохранение между сессиями не гарантируется.

## Эксперимент: влияет ли штраф за повторы на русский ответ

Откройте **Настройки и данные → Сравнить режимы ответа**, либо `compare.html`. По умолчанию сравниваются два прямых русских ответа одной Qwen3: с действующим штрафом `repetition_penalty=1.1` и без него, с эффективным значением `1.0`. Это проверка гипотезы по пользовательским отчётам, в которых даже простой рецепт омлета оказался бессмысленным; режим рассуждений также не исправил результат.

- Системный и пользовательский запросы одинаковы; перед каждым вариантом контекст сбрасывается. В обоих вариантах seed 42, temperature 0.7, top_p 0.8, лимит 512 токенов, `enable_thinking=false`. История чата не используется.
- Сначала выполняется обычный ответ со штрафом 1.1, затем ответ без штрафа. По умолчанию выбран запрос про омлет из двух яиц; доступны и прежние примеры про бегемота и свинку. Оценивать нужно смысл, русский язык и повторы. Одна пара с фиксированным seed не является статистическим бенчмарком.
- В WebLLM 0.2.79 публичный `chat.completions` **не передаёт `repetition_penalty`** из запроса в генератор. Для второго варианта явно задаются `frequency_penalty=0` и `presence_penalty=0`: реализация выбирает нулевые additive penalties вместо модельного множительного штрафа. Это эквивалентно отсутствию штрафов; приложение не притворяется, что поддерживается несуществующее поле запроса. При следующем обычном запросе нулевые значения не сохраняются, снова используется модельный штраф 1.1.
- Веса, контекст, GPU-устройство и основной чат не меняются. Повторная загрузка или вторая копия модели не требуются. Переводчик и дополнительные ресурсы не загружаются.
- Постепенный вывод, остановка и повторный запуск работают для обоих вариантов. Остановленный или ошибочный запуск не становится завершённым результатом. Достижение лимита сохраняется в JSON как `finish=length` и показывается предупреждением.
- JSON имеет `mode=penalty`, протокол `qwen3-ru-repetition-v1`, настройки обоих вариантов, фактически отправляемые нулевые штрафы, эффективный штраф каждого этапа, тексты и времена. Файл сохраняется только на устройство по кнопке.

Выбор ветви штрафов проверен на настоящем коде закреплённой WebLLM: публичный запрос проходит её преобразование настроек и метод сэмплирования. Для этого теста без GPU подменены тензорные операции, а не логика выбора штрафа; проверяются последовательность 1.1 → без штрафа → 1.1 и отсутствие изменения конфигурации. Это **не проверка генерации модели или качества русского языка на GPU**. Для такой проверки откройте страницу в совместимом Chrome и сохраните JSON, либо выполните `npm run test:gpu` на устройстве с подходящим адаптером.

## Эксперимент: русский ответ с рассуждениями и без

Предыдущий эксперимент сохранён: вкладка **«С рассуждениями и без»**, либо `compare.html?mode=thinking`. Сравниваются два прямых русских ответа одной Qwen3 1.7B. Обычный чат сохраняет прежний режим без рассуждений.

1. Нажмите «Запустить из кеша» или «Скачать Qwen и запустить». Используется тот же комплект весов: **858,4 МБ**, без новых моделей. Переводчик OPUS-MT и его WASM для этого эксперимента не загружаются.
2. Выберите запрос, например рассказ про бегемота из пользовательского отчёта, и нажмите «Сравнить ответы».
3. Сначала генерируется обычный русский ответ: `enable_thinking=false`, до 512 токенов. Затем после сброса контекста — русский ответ с `enable_thinking=true`, до **2048 токенов на рассуждения и ответ вместе**. WebLLM 0.2.79 не предоставляет независимых жёстких бюджетов для этих частей; поэтому итоговый ответ во втором варианте не ограничен отдельно 512 токенами. Это различие явно показано на странице и записано в JSON.
4. Системный и пользовательский запросы, seed 42, temperature 0.7, top_p 0.8 и repetition_penalty 1.1 одинаковы. История чата не используется. До запуска обоих вариантов проверяется, что запрос с большим резервом ответа помещается в контекст 4096 токенов; слишком длинный запрос отклоняется до первой генерации.
5. Во время рассуждений отображается состояние «Думает…». Их текст находится в отдельном раскрывающемся блоке и не попадает в панель итогового ответа. Если модель не завершила рассуждения, не выдала ожидаемый блок или не дала итоговый ответ, страница показывает предупреждение. Распознавание тегов работает и при разбиении тегов между фрагментами потока. Текст выводится безопасно, как текст.
6. Время справа включает рассуждения. JSON содержит оба ответа, отдельный текст и статус рассуждений, реальные времена, время до первого текста ответа и число сгенерированных токенов из WebLLM, если они предоставлены движком. Остановленный запуск не добавляется в завершённые результаты. Попытка, исчерпавшая лимит на рассуждения без ответа, сохраняется с явными признаками неполноты, чтобы её можно было изучить.

Результаты хранятся только в памяти вкладки, JSON сохраняется локально по кнопке. Настройки и протокол `qwen3-ru-thinking-v1` входят в файл. Переписка не меняется. Режим рассуждений может работать дольше и не гарантирует улучшения русского языка или точности. Бюджеты вариантов различаются, поэтому это практическое сравнение режимов, а не измерение качества при равной вычислительной стоимости. **Качество настоящей Qwen3 в этом режиме в облачной среде не подтверждено: нет совместимого GPU.** Для проверки на своём устройстве используйте страницу или `npm run test:gpu`; аппаратный тест сохраняет JSON для ручной оценки.

## Эксперимент: русский ответ через английский

Предыдущий эксперимент сохранён: вкладка **«Через английский»** на странице сравнения или `compare.html?mode=translation`. Только этот вариант дополнительно загружает OPUS-MT. Обычный чат продолжает отвечать напрямую на русском. Эксперимент не меняет историю и проверяет отдельные текстовые запросы.

1. Запустите Qwen и переводчик по кнопке. До нажатия ресурсы не скачиваются. Совместимость WebGPU проверяется до загрузки Qwen.
2. Выберите запрос и нажмите «Сравнить ответы». Этапы идут последовательно: прямой ответ Qwen на русском → перевод запроса Qwen RU → EN → английский ответ Qwen → перевод ответа OPUS-MT EN → RU на CPU в отдельном Worker.
3. Сравните два русских текста и промежуточный английский. Время варианта с переводом — сумма трёх этапов, без первоначальной загрузки. Это одиночная выборка, не статистический бенчмарк.
4. JSON сохраняется только на устройство по кнопке. Он содержит тексты, времена, версии обеих моделей и настройки. Автоматического победителя нет.

Qwen3 использует seed 42, режим рассуждений выключен; прямой и английский ответы — до 512 токенов. Для RU → EN остаётся явная задача перевода с примером, temperature 0, top_p 1, frequency_penalty 0, presence_penalty 0. В WebLLM 0.2.79 нулевые additive penalties отключают модельный repetition_penalty на этом этапе; обычные ответы сохраняют repetition_penalty 1.1.

Обратный перевод теперь выполняет **специализированная OPUS-MT**, а не Qwen. Старый `explicit-task-v2` правильно переводил запрос из пользовательского теста, но ответ искажал: «на сушу» превращалось в «на дно», pig — в «пиглох». Настройки генерации этого не исправили.

### Проверить готовый английский ответ без Qwen

Откройте `translate.html`: эта страница **не требует WebGPU**. Выберите сохранённый JSON сравнения — файл читается локально, берётся английский ответ последнего сравнения. Нажмите «Перевести». Так можно перепроверить прежний результат, не генерируя рассказ заново. Также можно вставить английский текст вручную и скачать отдельный JSON перевода.

### Ресурсы переводчика

| Параметр | Значение |
| --- | --- |
| Модель | Helsinki-NLP/opus-mt-en-ru, ONNX-конверсия Xenova/opus-mt-en-ru, q8 |
| Ревизия | `e050376e960175e8ddc5cff85025dc8436cddd68` |
| Лицензия модели и Transformers.js | Apache-2.0; ONNX Runtime — MIT; тексты лицензий копируются в ресурсы |
| Выполнение | Transformers.js 3.8.1, ONNX Runtime WASM, CPU, один поток в Worker |
| Первая загрузка | **83 699 926 байт ≈ 83,7 МБ** gzip: ONNX-энкодер и декодер, токенизатор, конфиги, WASM; JS дополнительно около 1 МБ |
| После распаковки | около 139 МБ; ориентир — ещё 0,5–1 ГБ свободной RAM для выполнения и временных буферов, это не гарантированный минимум |
| Ограничения | 12 000 символов на текст, до 400 исходных токенов и 384 новых токенов на предложение |

```bash
npm run translator:download
npm run translator:download -- --verify
# Для отдельного статического хранилища:
npm run translator:download -- --output /path/to/translations/opus-mt-en-ru
```

Загрузчик проверяет SHA-256 исходных ресурсов по закреплённому профилю и создаёт gzip-файлы с манифестом. Крупные файлы не входят в Git. `VITE_TRANSLATOR_BASE_URL` задаёт относительный путь (по умолчанию `translations/opus-mt-en-ru/`) или HTTPS-хранилище с теми же настройками CORS, что указаны для Qwen. WASM и модели загружаются только оттуда. JS выполнения остаётся частью сайта. Внешних CDN и API для перевода нет; удалённые модели в Transformers.js отключены.

Поддерживаются как бинарные `.gz` без Content-Encoding, так и хостинги с `Content-Encoding: gzip` (включая Vite preview). Worker распознаёт, распаковал ли браузер ответ: SHA-256 распакованного содержимого всегда проверяется по закреплённому профилю приложения. Если получены gzip-байты, дополнительно проверяется их SHA-256 по манифесту и выполняется распаковка. Ошибочный файл удаляется из кеша. Cache Storage `tetrikanets/opus-en-ru/<revision>` хранит полученные браузером ресурсы: сжатые или уже распакованные (до 139 МБ); `tetrikanets/translator-metadata-v1` — манифест. Кнопка «Удалить скачанный переводчик» на `translate.html` удаляет только эти кеши, сохраняя Qwen и историю.

**Каждое предложение переводится отдельно**, затем восстанавливаются исходные пробелы и абзацы. Передача абзаца целиком в эту sentence-level модель в реальном тесте приводила к пропускам предложений. Слишком длинное предложение или ответ, достигший лимита, завершаются понятной ошибкой; неполный перевод не выдаётся за готовый. «Остановить» использует InterruptableStoppingCriteria и передачу управления очереди сообщений между предложениями; на длинном предложении остановка может задержаться; через 6 секунд зависший Worker завершается принудительно.

Перевод всё ещё требует проверки: названия, термины, местоимения и необычные слова могут переводиться неточно. Английское выдуманное `henslope` из пользовательского рассказа не становится осмысленным названием животного. Markdown и блоки кода в этом текстовом эксперименте не защищены от перевода. Проверка длины отсекает грубые отклонения, но не оценивает смысл.

Playwright использует `/usr/bin/chromium`, если он установлен, иначе свой Chromium. Для своего браузера задайте `CHROMIUM_PATH`. На машине без браузера: `npx playwright install --with-deps chromium`.
