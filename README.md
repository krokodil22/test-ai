# Великий Тетриканец

Статический русскоязычный ИИ-чат: TypeScript, Vite и WebLLM. Генерация идёт
в Web Worker на GPU посетителя. После сборки нужны только статические файлы
и HTTPS. Сервер приложения, API нейросетей, аккаунты и платные ключи не нужны.
Сообщения не отправляются наружу; аналитики и телеметрии в приложении нет.

## Установка, разработка и сборка

Нужен Node.js 24 или новее. Python посетителям и для обычной сборки не требуется.

```sh
npm ci --ignore-scripts
npm run model:download
npm run model:download -- --verify
npm run translator:download
npm run translator:download -- --verify
npm run dev
```

Переводчик нужен только для эксперимента на `compare.html?mode=translation`
и страницы `translate.html`. Основной чат отвечает напрямую по-русски.
Для полного автономного комплекта сайта скачайте оба набора ресурсов.
Крупные файлы находятся в игнорируемых каталогах `public/models/` и
`public/translations/`; не добавляйте их в Git. Повторный запуск загрузчика
сохраняет проверенные файлы. Ревизии, размеры и хеши закреплены в
`scripts/model-source.json` и `scripts/translation-source.json`.

```sh
npm run build
npm run preview
```

Загрузите **содержимое `dist/`** на свой HTTPS-хостинг с сохранением каталогов.
Node.js-процесс на сервере не нужен. По умолчанию все адреса относительные:
эта сборка переносится в корень или подкаталог, не обращаясь к GitHub,
Hugging Face или CDN. Серверы исходных ресурсов используются загрузчиками
разработчика, а не для генерации ответов. Обычная сборка включает все
подготовленные ресурсы; она больше 2 ГБ и не помещается целиком в GitHub Pages.

## Модель и требования

| Параметр | Текущая пробная версия |
| --- | --- |
| Модель | Qwen3.5 4B, текстовый чат без режима рассуждений |
| Браузерные веса | `mlc-ai/Qwen3.5-4B-q4f16_1-MLC`, четырёхбитный MLC; не Ollama и не GGUF |
| Лицензия | Apache 2.0; копия в `licenses/Qwen3.5-APACHE-2.0.txt` и каталоге модели |
| Загрузка | Около **2,087 ГБ**, 82 ресурса: gzip-веса, WASM, токенизатор и конфигурация |
| Кеш распакованных ресурсов | Около **2,388 ГБ**, отдельно от скачанного архива |
| Выполнение | WebLLM **0.2.86**, библиотека WASM **v0_2_86/base**, версии и SHA-256 закреплены |
| Графическая память | Оценка WebLLM **3867,82 МБ** при контексте 4096; желательно GPU с 6 ГБ и запасом |
| RAM | Ориентировочно **6–8 ГБ свободной RAM**, предпочтительно устройство с 16 ГБ или больше |
| WebGPU | `shader-f16`; storage-буфер не меньше **317 849 600 байт / 303,1 МиБ**, обычно лимит адаптера от 512 МиБ |
| Контекст и ответ | 4096 токенов контекста, prefill 1024, ответ до 512 токенов |

Объёмы ГБ/МБ указаны в десятичной системе. Лимит загрузки повышен пользователем
до 2,1 ГБ после измерения комплекта. Это оценки памяти, а не проверенные
минимальные характеристики: свободная видеопамять через WebGPU не определяется.
Интегрированный GPU с общей памятью зависит от драйвера и лимитов браузера.
До скачивания проверяются HTTPS, адаптер, `shader-f16`, размеры буферов,
рабочая память группы от 32 КиБ и 10 storage-буферов на стадию. Устройство
получает достаточные `maxBufferSize` и `maxStorageBufferBindingSize`.

Источники: [исходная модель](https://huggingface.co/Qwen/Qwen3.5-4B),
[MLC-ресурсы](https://huggingface.co/mlc-ai/Qwen3.5-4B-q4f16_1-MLC),
[WebLLM](https://github.com/mlc-ai/web-llm).
Загрузчик исправляет ошибочные токены окончания в опубликованном MLC-конфиге:
используются ID **248044 и 248046**, соответствующие токенизатору Qwen3.5.
Исправленная конфигурация получает собственный SHA-256 в `model-info.json`.
Веса не изменяются. Не обновляйте только WASM или только библиотеку независимо.

## Качество и предварительная проверка

Замене предшествовали локальные CPU-проверки исходных весов нескольких семейств.
Запросы, настоящие ответы, точность, версии и настройки сохранены в
[`docs/model-evaluation/`](docs/model-evaluation/README.md). Это небольшой отбор,
не универсальный бенчмарк. Qwen3.5 4B лучше справилась с рецептом, объяснением
времён года, грамматикой и сохранением свинки/отрицания в коротком переводе.

**Ошибки в историях остаются:** в исходном жадном прогоне свинка «ходит по воде»,
а в прогоне с ограничением объёма у бегемота появляется рог. Некоторые ответы
достигают лимита. Не обещаем безошибочный русский или точность фактов.
Текущий системный запрос просит законченный короткий рассказ на 100–150 слов;
генерация использует temperature 0.7, top_p 0.8, repetition_penalty 1.0,
нулевые частотный штраф и штраф за присутствие, `enable_thinking=false`.

Контроль на `diagnostics.html` заранее сгенерирован исходной моделью на CPU
через Transformers 5.3.0 в **BF16**, без четырёхбитного квантования. При открытии
страницы эти большие исходные веса не скачиваются: читается только JSON.
Он проверяется по модели, ревизии, точности, протоколу и запросам. Это не
генерация на CPU посетителя и не FP32. Браузерная четырёхбитная версия может
отвечать иначе; точное совпадение текстов не ожидается.

В облачной среде нет совместимого GPU, поэтому **аппаратная генерация новой
WebLLM-модели здесь не подтверждена**. Её надо проверить на целевом устройстве
в актуальном настольном Chrome. Совместимость с Яндекс Браузером, телефонами,
Safari и Firefox не проверена и не обещается.

## GitHub Pages

Pages ограничивает размер сайта 1 ГБ. Поэтому workflow публикует интерфейс,
локальные библиотеки, переводчик и манифест в Pages, а большой архив модели —
в **Releases этого же репозитория**. Отдельное хранилище или ключи не требуются.

1. Отправьте исходники в `main`: публикация запускается автоматически при изменении приложения.
2. В **Settings → Pages → Build and deployment** выберите **GitHub Actions**.
3. Запустите **Actions → Publish GitHub Pages → Run workflow → main**.
4. Дождитесь успешного завершения build и deploy.

Workflow скачивает и проверяет ресурсы, создаёт архив, публикует его вместе
с лицензией, собирает сайт для `/<имя-репозитория>/` и проверяет размер Pages.
Для публикации Releases шагу сборки нужен стандартный `contents: write`;
используется `github.token`, платные или пользовательские API-ключи не нужны.
Повторный запуск использует тег, содержащий модель и закреплённую ревизию.
Запускайте новую workflow на `main`: повтор старой job использует старый код.

При первом открытии посетитель после проверки GPU скачивает `.tar` по ссылке
и выбирает его на странице. **Файл не загружается на сервер:** Worker читает
его локально, проверяет заголовки TAR, версию, размеры, оба SHA-256 и сохраняет
распакованные ресурсы в кеш WebLLM. Большой архив и весовой шард не читаются
целиком в JavaScript RAM; распаковка и хеширование выполняются потоком.
Повторный запуск использует кеш без выбора файла. Архив после импорта можно
удалить с диска; при очистке кеша он понадобится снова.

GitHub Releases не гарантирует CORS для браузерного `fetch`, поэтому используется
обычное скачивание и локальное открытие файла. Для своего хостинга применяйте
**обычный `npm run build`**: он содержит файлы рядом с сайтом и не зависит от
Releases. Менять код приложения для переноса не нужно.

Ручная подготовка варианта Pages:

```sh
npm run model:archive
npm run build:pages
node scripts/check-pages-size.mjs
```

Архив появится в `.cache/qwen35-4b.tar`. Самостоятельная публикация архива:
`node scripts/publish-model-release.mjs` с авторизованным GitHub CLI.
Для форка задайте `MODEL_RELEASE_REPOSITORY=owner/repository`;
в Actions значение берётся из `GITHUB_REPOSITORY` автоматически.
`VITE_MODEL_ARCHIVE_URL` позволяет явно задать HTTPS-ссылку на архив.

## Адреса ресурсов и CORS

Скопируйте `.env.example` в `.env.local`, если нужно изменить адреса.

```dotenv
VITE_BASE_PATH=./
VITE_MODEL_BASE_URL=models/qwen35-4b/
VITE_TRANSLATOR_BASE_URL=translations/opus-mt-en-ru/
```

Для отдельного собственного хранилища можно задать
`VITE_MODEL_BASE_URL=https://storage.example/models/qwen35-4b/`.
Разместите там **весь** подготовленный каталог модели, сохранив `resolve/main/`.
Для переводчика аналогично доступен `VITE_TRANSLATOR_BASE_URL`.
Адреса задаются при сборке. По умолчанию внешних адресов нет.

Хранилищу нужны HTTPS без редиректов и заголовки CORS для origin сайта:

```http
Access-Control-Allow-Origin: https://owner.github.io
Access-Control-Allow-Methods: GET, HEAD, OPTIONS
```

Для общедоступных весов допустим `Access-Control-Allow-Origin: *`.
Cookie и credentials не передаются; `Access-Control-Allow-Credentials` не нужен.
Типы: WASM — `application/wasm`, JSON — `application/json`, веса и `.bin.gz` —
`application/octet-stream`. Для `.bin.gz` достаточно отдавать исходные байты
без `Content-Encoding`; вариант с автоматической HTTP-распаковкой gzip также
поддержан и проверен. Не подменяйте отсутствующие файлы страницей `index.html`.
Приложению не требуются специальные COOP/COEP-заголовки.

## Интерфейс, данные и приватность

- Enter отправляет, Shift+Enter добавляет строку; IME-композиция учитывается.
- Ответ выводится постепенно. Есть остановка, новый чат, Markdown, подсветка
  кода и копирование. HTML из сообщений не исполняется; изображения и внешние
  ссылки из ответов не загружаются.
- Параллельные генерации запрещены. Зависший Worker после остановки завершается;
  при продолжении используются сохранённые файлы. На потерю GPU, нехватку RAM,
  ошибку сети/хеша и невозможность записи кеша показывается понятное сообщение.
  Переключения на внешние API нет.
- Контекст включает системный запрос и свежие полные пары реплик. Старые реплики
  исключаются из контекста, оставаясь в видимой истории. Длинный вопрос отклоняется
  до генерации. История ограничена 30 чатами по 500 сообщений.
- Переписка хранится в `localStorage` (`ryadom:chats:v1`), ресурсы — в Cache Storage:
  `webllm/model`, `webllm/config`, `webllm/wasm`, `ryadom/metadata-v1`.
  Удаление истории и модели разделено. Старые версии Qwen2.5/Qwen3 удаляются
  адресно; переписка, переводчик и чужие кеши сохраняются.
- Кеш зависит от origin и профиля браузера. Приватный режим и нехватка места
  могут мешать сохранению; браузер вправе удалить кеш. История не зашифрована
  от других пользователей того же профиля и расширений с соответствующим доступом.
- Хостинг видит GET статических файлов и IP посетителя, но приложение не отправляет
  тексты сообщений и ответов. Worker ограничивает запросы каталогом модели;
  CSP запрещает произвольные внешние соединения. Встроенного гарантированного
  офлайн-запуска страницы нет: при открытии интерфейсу нужен хостинг.

## Сравнение и диагностика

- `compare.html?mode=translation`: прямой русский ответ и цепочка
  RU → EN → английский ответ → EN → RU. Последний перевод выполняет локальный
  OPUS-MT на CPU; ресурсы и WASM размещаются вместе с сайтом. Смысл перевода
  может теряться; этот режим остаётся экспериментом, основной чат его не использует.
- `compare.html?mode=penalty`: одинаковый запрос со штрафом 1.1 и без него.
  В WebLLM 0.2.86 множитель передаётся напрямую в каждом запросе.
- `compare.html?mode=thinking`: обычный ответ и режим рассуждений с бюджетом
  2048 токена вместе с итоговым ответом. Незавершённые рассуждения не выдаются
  за готовый ответ; улучшение качества не гарантируется.
- `diagnostics.html`: шесть RU/EN заданий с нейтральной инструкцией и жадным
  декодированием, повторная SHA-проверка кеша, доступные сведения об адаптере
  и рабочем устройстве, сравнение с настоящим CPU-контролем.

Каждый этап начинается без истории. Остановка, ошибки и достижение лимита
помечаются в отчёте; незавершённый запуск не считается полным. JSON сохраняется
только на устройство по кнопке, без аналитики или автоматической отправки.

## Проверка

```sh
npm test
npm run test:e2e
npm run build
npm run test:gpu
```

Playwright использует установленный `/usr/bin/chromium` либо свой браузер.
Можно указать `CHROMIUM_PATH`; установка браузера:
`npx playwright install --with-deps chromium`.

Проверены сборка и относительные пути в корне/подкаталоге, Worker-протокол,
потоковый вывод, Enter/Shift+Enter, остановка и повторная генерация, независимая
очистка, кеш без повторных загрузок, безопасный Markdown, ошибки и CORS на втором
origin. Интерфейс проверен также в эмулированном размере 390×844; это не проверка
настоящего телефона. Модульные проверки передачи штрафов используют настоящий
код WebLLM без GPU. E2E-генерация подменяется явно помеченным тестовым движком
только при `E2E_MOCK=1`; такую сборку нельзя публиковать.

Отдельно проверен настоящий импорт архива Phi‑4 mini на 1,908 ГБ и полный
SHA-аудит 70 файлов / 2,178 ГБ без запросов весов. Это проверка файлов и кеша,
не генерации. Результат: `docs/model-evaluation/archive-import-check.json`.
Для конечной Qwen3.5 4B также выполнен холодный импорт 82 файлов, полный аудит
2 387 631 807 байт и повторное использование кеша без запросов весов:
`docs/model-evaluation/qwen35-archive-import-check.json`.
OPUS-MT проверяется на настоящих ONNX/WASM: отрицание, персонажи, абзацы,
кеш, остановка, очистка, SHA-ошибки и отсутствие отправки текста.

Проверки настоящей генерации WebLLM на совместимом GPU в облаке **пропущены**,
а не объявлены успешными. На целевом компьютере проверьте: импорт/скачивание →
вопрос по-русски → остановка → обновление и запуск из кеша → удаление модели →
отдельная очистка истории. В DevTools Network должны быть только GET настроенных
статических ресурсов, без текста переписки и повторной загрузки весов из кеша.
